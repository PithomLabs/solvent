## 7. Action Intent Attack

### Lifecycle

| State | Transition | Mechanism |
|-------|-----------|-----------|
| `live` | Creation | `kernel.IntentOnPromoted` — DB-gated by composite FK |
| `live` | Cancellation | `kernel.RetractCascade` — cancels then retracts |
| `cancelled` | Final | Immutable after cancellation |

### Findings

1. **Intent creation is DB-gated**: `sqlIntentOnPromoted` inserts only if belief is currently promoted (composite FK).
2. **Intent cancellation is atomic**: `RetractCascade` cancels live intents before retracting beliefs in one transaction.
3. **No intent modification**: No code modifies `action_intent` rows after creation.
4. **Replay prevention**: `pipeline.ProposeIfNew` checks for existing live intents before creating. `kernel.IntentOnPromoted` itself is NOT idempotent (documented v0 limitation).
5. **Intent ≠ authority**: No code treats intent state as authority. `internal/view/explain.go` computes `CanAuthorize` from belief status, not intent state.

**Can an intent become executable without current authority?** No — no execution path exists.

**Can an old intent bypass a new authorization decision?** No — no execution path exists.

**Can actor/action/target be changed after authorization?** No — no code modifies intent rows.

## 20. Replay Attack

### Findings

1. **Intent creation**: `kernel.IntentOnPromoted` is NOT idempotent (documented v0 limitation). A retry after successful commit but before client receives response creates a duplicate intent row.
2. **Intent proposal**: `pipeline.ProposeIfNew` prevents duplicate intents for the same belief/action pair by checking first.
3. **Debt discharge**: `kernel.Discharge` is idempotent (UNIQUE constraint on belief_id + obligation_key + instrument_ref).
4. **Authority creation**: `kernel.Approve` would fail on duplicate activation (UNIQUE constraint on target_activation.target_id).

**No global replay prevention exists. This is a documented v0 limitation.**

## 25. Findings by Severity

### CRITICAL
**None.**

### HIGH

#### F-1: No Production Execution Path

**File:** `service/authority/authority.go`
**Function:** `ExecuteAction`
**Attack Scenario:** The remediation established a security boundary in `ExecuteAction`, but no production code calls it. The executor registry is empty. There is no route, handler, or tool that can invoke any executor.
**Why It Works:** Exhaustive search of all production entry points (wizard routes, MCP tools, CLI commands, adapters) reveals zero callers of `ExecuteAction`.
**Expected Behavior:** Every consequential production execution path reaches `ExecuteAction` → `PrepareForAction` → `kernel.Authorize` → `Executor`.
**Actual Behavior:** `ExecuteAction` is dead code. No production execution path exists.
**Exploitability:** N/A — nothing can execute today
**Security Impact:** The security boundary is unreachable from production. If a future developer wires an executor to a production path without going through `ExecuteAction`, there is no authority check.
**Recommended Fix:** Wire `ExecuteAction` into production paths before Phase 4, or document that execution is intentionally deferred and remove the dead code.
**Code Change Required:** Yes.

#### F-2: Workflow Service Is Dead Code

**File:** `service/workflow/workflow.go`
**Function:** All
**Attack Scenario:** The workflow service implements token lifecycle management, but it is not imported anywhere in production code. Its security boundary (token state machine) is unreachable.
**Why It Works:** Grep for `service/workflow` imports in production code returns zero results.
**Expected Behavior:** Workflow tokens gate execution through the state machine.
**Actual Behavior:** Workflow tokens are never created or used in production.
**Exploitability:** N/A — dead code
**Security Impact:** If a future developer imports `service/workflow` and treats token state as authority, there is no enforcement because the token state machine is disconnected from `kernel.Authorize`.
**Recommended Fix:** Either wire workflow tokens into the execution path or remove the dead code.
**Code Change Required:** Yes.

### MEDIUM

#### F-3: `operator-review` CLI Bypasses `PrepareForAction`

**File:** `cmd/operator-review/main.go`
**Function:** `runReviewMode`
**Attack Scenario:** The CLI calls `kernel.IntentOnPromoted` directly without `PrepareForAction` authority verification. This skips the authority layer.
**Why It Works:** Line 167: `st.IntentOnPromoted(ctx, scenarioID, beliefID, action)` is called directly.
**Expected Behavior:** All intent creation should go through `PrepareForAction` for authority verification.
**Actual Behavior:** The CLI bypasses the authority service and calls the kernel directly.
**Exploitability:** Low — CLI is a trusted administrative tool, not a production server
**Security Impact:** An operator with CLI access can create intents without authority verification. The database still enforces belief promotion via the composite FK.
**Recommended Fix:** Call `authSvc.PrepareForAction` before `IntentOnPromoted` in the CLI, or document that the CLI is a trusted administrative tool that bypasses the authority layer.
**Code Change Required:** No — this is a CLI tool, not a production server.

#### F-4: MCP `solvent_authorize_action` Conditionally Skips `PrepareForAction`

**File:** `cmd/solvent-mcp/tools.go`
**Function:** `handleSolventAuthorizeAction`
**Attack Scenario:** When `target_id` or `actor_id` are missing from the request, `PrepareForAction` is skipped. The MCP tool creates an intent without authority verification.
**Why It Works:** Lines 248-264: `if targetID != "" && actorID != ""` guards the `PrepareForAction` call.
**Expected Behavior:** Every intent creation should be authority-verified.
**Actual Behavior:** Intent creation without authority verification when target/actor are missing.
**Exploitability:** Low — intent creation only, not execution. Database still enforces belief promotion.
**Security Impact:** An MCP client can create intents without authority verification by omitting target/actor IDs.
**Recommended Fix:** Either require `target_id` and `actor_id` for all intent creation, or document that missing fields mean "no authority verification."
**Code Change Required:** No — this is intent creation, not execution.

### LOW

**Attack Scenario:** Policy constraints are never evaluated in any production execution path because no execution path exists.
**Why It Works:** `EvaluateConstraints` is never called from any production handler, route, or tool.
